# WP-0098: Talvik Native Inference Performance and Worker Isolation

## Purpose

Make interactive local inference responsive and bounded without changing the
public model identity, scheduler, authentication, or llama.cpp engine.

## Source evidence

- Continue reached Qwen through Talvik but a short request remained active and
  produced repeated Markdown.
- `NativeModel::generate_stream` created a fresh context for every request and
  previously detokenized all generated tokens on each callback.
- A native assertion previously aborted the whole daemon.
- The local reference implementation at
  `f52b9e742d8c9a308f7b23cd1f0ab52c7ddb694d` uses persistent per-model serving
  processes, prompt caching, bounded batch controls, complete sampling/stop
  translation, repetition protection, and phase-specific timings.

## Dependencies

ADR-0026; WP-0027, WP-0031, WP-0034, WP-0058, WP-0062, WP-0091, WP-0094.

## Scope

1. Complete the bounded-batch, incremental-decoding, request-option, terminal
   marker, and phase-timing Stage A changes.
2. Add request stop sequences and bounded repetition protection.
3. Design and implement supervised per-model native workers behind the current
   backend contract.
4. Add safe prompt-prefix/KV reuse with deterministic cache invalidation.
5. Preserve exact model selection, FIFO one-active scheduling, cancellation,
   pinning, memory admission, and unload semantics.
6. Qualify native compiler/CPU dispatch and library packaging per platform.

## Acceptance criteria

- Short bounded prompts terminate with `stop` or `length`; no request remains
  active after its terminal SSE chunk and `[DONE]`.
- A prompt larger than the physical batch decodes without assertion or silent
  truncation.
- Supported sampling and token-budget controls reach the native adapter;
  unsupported controls are not silently discarded.
- Incremental output assembly is linear in generated bytes.
- Repeated prompt prefixes demonstrate measured cache reuse without leaking
  context into an unrelated request.
- A deliberately failed native worker does not terminate the daemon or another
  resident model, and the failed model can reload.
- Metrics separate queue wait, model load, prompt evaluation, first token,
  generation throughput, and termination.
- Real GGUF measurements record model digest, context, batch, thread settings,
  host CPU/RAM, TTFT, prompt tokens/s, generation tokens/s, and peak memory.
- Workspace tests and strict Clippy pass.

## Automated tests

- Generation-option mapping and precedence.
- Complete versus partial terminal marker handling.
- Prompt chunking above 512 tokens.
- Cancellation and stream terminal behavior.
- Context-cache key and invalidation behavior.
- Worker crash/restart and cross-model isolation.
- Repetition guard and explicit stop sequences.

## Native qualification

Run an uncontended baseline and changed build with Qwen and one second model on
each advertised platform. Compare cold load, cold TTFT, warm TTFT, prompt
evaluation, generation throughput, cancellation latency, and memory. A build
or mock test is not native performance qualification.

## Status

In progress. Stage A is implemented and deterministic tests pass. Native Qwen
smoke runs against isolated release binaries completed without the prior batch
assertion. The first bounded eight-token run finished in 12.533 seconds, with
7.410 seconds prompt evaluation and 7.411 seconds to first token. The final
committed-source binary finished the same request in 18.534 seconds, with
10.329 seconds prompt evaluation, 10.350 seconds to first token, and 0.432
generated tokens per second. Both reported `finish_reason=length`, 29 prompt
tokens, and 8 completion tokens. The variation while the older production
daemon remained resident confirms functional correctness but does not qualify
performance. The run exposed and corrected a dropped throughput metric at the
runtime bridge. Persistent workers, prompt/KV reuse, stop controls, repetition
protection, and crash isolation remain OPEN.
